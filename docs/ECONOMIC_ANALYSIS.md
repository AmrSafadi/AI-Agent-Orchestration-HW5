# Economic Analysis

## Purpose

This note records the Phase 8 on-prem versus API cost comparison. The numbers
are generated by:

```powershell
uv run python experiments/run_economics.py
```

The script writes:

- `results/economics_summary.json`
- `results/economics_curve.csv`
- `figures/cost_break_even.svg`

## Assumptions

| Field | Value |
| --- | --- |
| Pricing date | 2026-06-20 |
| API provider/model | OpenAI `GPT-5.4 mini` |
| API input price | $0.75 per 1M tokens |
| API cached input price | $0.075 per 1M tokens |
| API output price | $4.50 per 1M tokens |
| Local hardware cost | $700 |
| Hardware lifetime | 36 months |
| Electricity price | $0.20/kWh |
| Estimated inference power draw | 45 W |
| Measured local workload | 23 input tokens, 32 output tokens, 13.4804 seconds |

The API model is an illustrative external-service comparison point, not a claim
that it is quality-equivalent to Qwen 2.5 3B Q4_K_M.

## Result

For the measured GGUF workload:

- API cost per request: about `$0.000161`.
- Local variable electricity cost per request: about `$0.0000337`.
- Local fixed amortized hardware cost: about `$19.44/month`.
- Break-even without cached input: about `152,447` similar requests/month.
- Break-even with 80% cached input: about `168,893` similar requests/month.

## Interpretation

At low volume, the API path is economically better because the local machine has
a fixed monthly amortized hardware cost. At high volume, local inference becomes
cheaper per request because the variable electricity cost is much lower than the
API token charge.

The economic recommendation is therefore workload-dependent:

- Prefer API usage for low-volume, high-quality, bursty, or maintenance-free
  workloads.
- Prefer local/on-prem inference when privacy, offline control, predictable high
  volume, or experimentation with local model formats matter enough to justify
  hardware ownership and operational friction.
